### Multi-tenancy (IMPORTANT)
**One MySQL schema per (company × fiscal year).**
```
JWT → req.user{companyId, yearId}
  → middleware/tenantContext.js  → resolves dbName, enters AsyncLocalStorage
  → connection.js getPoolForDb(dbName)  → per-DB pool (cached, max 30, idle-evicted)
  → ALL downstream connection.query() uses tenant pool
```
- Meta DB = `DB_NAME` (default `shreehkweb_snj2024_test`).
- `META_ONLY_PREFIXES` always hit meta DB: `/user/`, `/session/`, `/portal/`, `/admin/*`, `/manage-user/`, `/role-*`, `/config/`, `/health`.
- **Row-level:** most tables have a `company` column. Every SELECT/UPDATE/DELETE must filter `company = ?`.

### Auth & permissions
- JWT: `jwt.sign({user_id, username, roll, jti, companyId, yearId}, SECRET_KEY, {expiresIn:'2h'})`. Issued at `POST /user/login` and re-issued at `POST /session/context` (on company/year switch).
- `authenticateToken` → verify → blacklist check (`jti` in-memory map) → `touchUserPresence` → refresh audit ctx → attach tenant ctx.
- `enforceApiPermission` (global) → maps URL → page key via `config/permissionRegistry.js` `apiPrefixes` → checks `roll.resource` → 403 `FORBIDDEN_PAGE`.
- 65 page keys across 7 modules. `roll === 1` = super admin (bypass all).
- Rate limits: global 300/min; login 50/15min; lab fetch 60/min per company.

### Audit trail (3-stage auto + explicit)
1. `attachAuditContext` → ALS store (user, role, ip, ua, page path, preSnapshot).
2. `auditPreSnapshot` → looks up rule by `METHOD+path` in `config/auditSnapshotRegistry.js` (47 rules) → fetches row before mutation.
3. `auditHttpLogger` → on `res.finish`, if 2xx & not already audited → infers actionType (CREATE/UPDATE/DELETE/API_READ/EXPORT/PRINT) → diffs fields → writes to `dai_activity_log` **in the meta DB**.
Explicit audits via `services/auditIntegration.js` → `logAudit()` / `logAuditInTx()`.

### 4-layer architecture (MANDATORY for new routes)
```
routes/<module>/<name>Routes.js        → HTTP only (parse, validate, call service, respond)
validators/<module>/<name>Validation.js → parse / validate / normalize
services/<module>/<name>Service.js      → business logic + audit triggers
repositories/<module>/<name>Repository.js → raw SQL, parameterized, `company = ?`
```
**Gold standard exemplars:**
- `routes/accounting/expensePaymentRoutes.js` → `validators/accounting/expensePaymentValidation.js` → `services/accounting/expensePaymentService.js` → `repositories/accounting/expensePaymentRepository.js`
- `routes/transaction/companyTransferRoutes.js` → `validators/transaction/companyTransferValidation.js` → `services/transaction/companyTransferService.js` → `repositories/transaction/companyTransferRepository.js`
- `routes/lab/labRoutes.js` → `validators/lab/labValidation.js` → `services/lab/labService.js` → `repositories/lab/*`

**Legacy 2-layer still present** (convert to 4-layer if touched): `routes/master/*`, `routes/inward/inwardRoutes.js`, `routes/report/*`, `routes/outward/outwardRoutes.js`, `routes/product/*`.

## 3. BUSINESS DOMAIN — Diamond lifecycle

```
INWARD  → dai_inward + dai_product + dai_product_value
          visibility=1, outward=NULL → In Safe (on-hand)
              ↓
OUTWARD → dai_outward + dai_product.outward = 'memo'|'consign'|'sale'|'export'|'lab'
              ↓
     Return (outward=NULL) | Convert to Sale | Convert to Consignment
```

`dai_product` key state fields:
| Field | Values |
|---|---|
| `visibility` | 1 active / 0 archived |
| `hold` | 1 / 0 (auto-release via expiry cron) |
| `outward` | NULL = in safe, memo, consign, sale, export, lab |
| `pair` | SKU of matched partner |

**Accounting (double entry, `acc_transaction`):**
- Sale → Party **DR** / Diamond Sales **CR**
- Purchase → Diamond Purchase **DR** / Supplier **CR**
- Payment received → Bank/Cash **DR** / Party **CR**
- Books: Bank, Cash, Journal, Purchase, Sale

### From `.agents/rules/shreehk-erp-project-development-rules-architecture-standard.md`

7. SCSS: use `_variables.scss` tokens, never hardcoded hex.
